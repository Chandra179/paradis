# Information extraction methods and evaluation

## What information extraction needs to recover

Information extraction converts passages and structured source fields into records that a program can query and a person can verify. The target determines what counts as a correct record. General methods can propose mentions and relations before the target is settled. A particular question determines which roles, qualifiers, and evidence the result needs.

The ferry walkthrough illustrates the distinction. Detecting a date, a route name, and an interval gives three useful candidate spans. A usable record establishes that the dates delimit the **scheduled ferry suspension** and that the interval describes the **replacement shuttle**. It also carries the inspection condition and leaves the actual restart date unknown. Checking whether a date falls in the scheduled window is a downstream operation over that record.

| Extraction task | Output | Main source of error |
| --- | --- | --- |
| Mention detection and typing | Text spans and types for names, dates, quantities, concepts, or event triggers. | Missing a mention or assigning an incorrect boundary or type. A trigger identifies a possible event. [GLiNER](https://aclanthology.org/2024.naacl-long.300/) · [MAVEN](https://aclanthology.org/2020.emnlp-main.129/) |
| Normalization | Canonical value with its literal form, unit, precision, range or bound, and any reference time. | Losing qualifiers, binding quantities to the wrong concept, or guessing a date anchor. CQE combines unit dictionaries with dependency parsing to attach measurements to concepts. SUTime uses rule-based temporal normalization. [CQE paper](https://aclanthology.org/2023.emnlp-main.793/) · [CQE implementation](https://github.com/vivkaz/CQE) · [SUTime](https://aclanthology.org/L12-1122/) |
| Coreference and entity linking | A cluster of mentions that refer to the same object, or a link to a known identifier. | A pronoun or alias can refer to multiple candidates. Cross-document linking introduces collisions between entities with the same name. Use an unresolved state where evidence is insufficient. [Neural coreference](https://aclanthology.org/D17-1018/) · [BLINK entity linking](https://aclanthology.org/2020.emnlp-main.519/) |
| Open relation extraction | Candidate predicate and arguments, often a subject–relation–object tuple, with qualifiers when the method supports them. | Different wordings can express the same relation. A flattened tuple can lose attribution, conditions, or argument scope. [ReVerb](https://aclanthology.org/D11-1142/) · [OLLIE](https://aclanthology.org/D12-1048/) |
| Typed relation or event extraction | A known relation type between entities, or an event with a trigger and several named roles. | Correct spans can still attach to the wrong event. Some arguments occur in separate sentences. Document-level evidence can require several passages. [Odin](https://aclanthology.org/P15-4022/) · [DocRED](https://aclanthology.org/P19-1074/) · [RAMS](https://aclanthology.org/2020.acl-main.718/) |
| Attribution, polarity, and modality | Who reports or asserts the content, the reporting cue, and whether the content is asserted, negated, conditional, planned, or uncertain. | A publisher may quote another speaker. Negation or uncertainty can govern one clause or an embedded statement. Keep attribution and scope attached to the affected assertion. [PARC 3.0](https://aclanthology.org/L16-1619/) · [FactBank guidelines](https://catalog.ldc.upenn.edu/docs/LDC2009T23/annotationGuidelines.pdf) |
| Discourse and procedural extraction | Relationships such as a stated reason or condition, or steps with their ordering, prerequisites, and state changes. | Co-occurrence and temporal order alone provide weak evidence for causality. A procedure can contain branches and conditions that span paragraphs. Extract the text's reported relation and its evidence. [RECESS](https://aclanthology.org/2023.ijcnlp-main.6/) · [ProPara](https://aclanthology.org/N18-1144/) |

These tasks can be combined as the output requires. Entity recognition can contribute spans to several goals. The event schema decides which roles apply, how they attach, and when the system can publish a result. Association rules, predictions, and causal inference over the resulting records require their own validation.

## Approaches and when to use them

| Approach | How it works | Practical starting point and limitation |
| --- | --- | --- |
| Structured source mapping | Read known fields from feeds, APIs, HTML metadata, or schema markup and preserve a field-level locator. | Use wherever the publisher supplies the needed fields. Expect missing fields, conflicting metadata, and differing source semantics. Retain both values and provenance when they disagree. [Schema.org Article](https://schema.org/Article) |
| Regex, dictionaries, and token rules | Use surface matches for recognizable forms, aliases, cue words, and bounded token sequences. | A cheap, interpretable baseline for literals and predictable text. Precision depends on context and attachment guards. An expanding list of site or topic exceptions raises maintenance cost. [spaCy rule matching](https://spacy.io/usage/rule-based-matching) · [SUTime rules](https://stanfordnlp.github.io/CoreNLP/sutime.html) |
| Dependency and role patterns | Parse the sentence, then match typed triggers and paths to arguments and context cues. | Useful when wording varies through reordering, passives, and modifiers. Odin and Odinson provide working patterns over token and dependency graphs. Test the downstream impact of parser errors on the actual page types. [Odin](https://aclanthology.org/P15-4022/) · [Odinson paper](https://aclanthology.org/2020.lrec-1.267/) · [Odinson source](https://github.com/lum-ai/odinson) |
| Open information extraction | Identify candidate predicates and arguments without enumerating the target relation vocabulary. ReVerb uses syntactic and lexical constraints, and Stanford OpenIE uses clause simplification and hand-built patterns after learned clause splitting. | Use for candidate discovery and broad baselines. Normalize paraphrases and validate argument completeness and context when records feed a query. Open extraction and typed extraction can consume the same text and serve different outputs. [ReVerb software](https://reverb.cs.washington.edu/) · [Stanford OpenIE paper](https://aclanthology.org/P15-1034/) · [CoreNLP source](https://github.com/stanfordnlp/CoreNLP) |
| Supervised tagging and classification | Learn span labels, entity types, role assignments, or relationship classes from examples. A sequence tagger or encoder that scores spans is a non-generative option. | Test when a field has recurring paraphrases that make rules brittle. GLiNER is a research comparator for label-conditioned entity spans. Relation classification and semantic validation are separate tasks. For scarce labels, Snorkel shows how noisy labeling functions can generate training signals, with a separately labeled evaluation set. [GLiNER paper](https://aclanthology.org/2024.naacl-long.300/) · [GLiNER code](https://github.com/urchade/GLiNER) · [Snorkel paper](https://www.vldb.org/pvldb/vol11/p269-ratner.pdf) · [Snorkel code](https://github.com/snorkel-team/snorkel) |
| Schema-conditioned generation | Give a model target labels, structure, and guidelines, then generate candidate records. UIE demonstrates a schema-based formulation. GoLLIE studies the contribution of annotation guidelines in zero-shot extraction. | A later comparator for ambiguity, recall, or schema changes that justify its cost. Constrain the output shape, require source spans, and validate attachment and claim support. Schema validation alone checks structure. Evaluate on the same frozen documents and count unsupported fields alongside latency and cost. [UIE](https://aclanthology.org/2022.acl-long.395/) · [GoLLIE paper](https://arxiv.org/abs/2310.03668) · [GoLLIE implementation](https://github.com/hitz-zentroa/GoLLIE) |

Rules and models can cooperate. A small model can find candidate spans, a normalizer can convert their literal values, and rules can enforce attachment and abstention. For broad candidate discovery, an Open IE system can run alongside a typed extractor. The findings in these papers describe their specific tasks and corpora. Use head-to-head tests before choosing a method for web pages in this project.

## Designing a reusable extraction contract

Start with versioned text or structured fields. Carry the title, section headings, neighboring paragraphs, and table headers where they are necessary to interpret a value. Within each document, allow extraction to use the smallest context that gives sufficient evidence. Measure a sentence-only baseline and expand to paragraph or document context when roles frequently span sentences. RAMS explicitly evaluates this cross-sentence argument problem. [RAMS paper](https://aclanthology.org/2020.acl-main.718/)

A candidate record can carry a type, literal and normalized values, status or uncertainty, the source and document version, and one or more evidence spans for each material field. A text span needs exact offsets and its normalization version. For an API or feed field, use an immutable response reference and a field path. When one passage identifies a subject and another supplies its value, preserve both. Record the extractor, rule or model version, and the reason when a candidate is withheld.

Validate at two levels. **Mechanical evidence validation** checks that the offsets resolve to the quoted bytes and that the specified source version is inspectable. **Semantic evidence validation** checks that the passage supports the field, its role, its qualifier, and its attribution. Review both in the benchmark. Represent missing optional values explicitly and let a candidate abstain when a required field or supporting span is ambiguous. Combine facts across documents only with an evidence trail that preserves source independence and conflicts. [W3C Web Annotation](https://www.w3.org/TR/annotation-model/) · [W3C PROV](https://www.w3.org/TR/prov-dm/)

Extraction confidence, evidence support, and source credibility are separate. A reliable extraction can report what an unreliable source said. A source can also publish two different values at different times. Preserve both versions and their dates so downstream logic can distinguish contradictions from updates.

## Benchmark choices and their limits

| Research question | Benchmark or reference | Match to this project |
| --- | --- | --- |
| Can a method recover open relations? | CaRB and BenchIE. BenchIE groups equivalent expressions of facts to address scoring sensitivity to wording. | Use as published comparisons, with a manual web sample for attribution, scope, and evidence. [CaRB](https://aclanthology.org/D19-1651/) · [BenchIE](https://aclanthology.org/2022.acl-long.307/) |
| Can it recover typed relations across sentences? | DocRED and Re-DocRED. The latter study found missed positives in DocRED and added annotations. | Use for relation coverage and document context. Treat incomplete labels carefully when judging alleged false positives. [DocRED](https://aclanthology.org/P19-1074/) · [Re-DocRED](https://aclanthology.org/2022.emnlp-main.580/) |
| Can it detect events and attach their arguments? | MAVEN for event triggers and types. RAMS or WikiEvents for argument attachment across sentences. | Score argument roles separately from trigger detection. Their inventories and text distributions are fixed by the datasets. [MAVEN](https://aclanthology.org/2020.emnlp-main.129/) · [RAMS](https://aclanthology.org/2020.acl-main.718/) · [WikiEvents paper](https://aclanthology.org/2021.naacl-main.69/) |
| Can it preserve who said what and the status of the claim? | PARC for source, cue, and content. FactBank for source-relative factuality. RECESS for reported causal spans. | Use to inform annotation and build targeted challenge cases. Each corpus covers a different part of the evidence contract. [PARC](https://aclanthology.org/L16-1619/) · [FactBank guidelines](https://catalog.ldc.upenn.edu/docs/LDC2009T23/annotationGuidelines.pdf) · [RECESS](https://aclanthology.org/2023.ijcnlp-main.6/) |
| Can the linguistic analysis support dependency rules? | Universal Dependencies English Web Treebank and the Stanford Stanza pipeline. | Check parsing and tokenization locally, then measure whether improvements carry through to extracted records. [English Web Treebank](https://universaldependencies.org/treebanks/en_ewt/index.html) · [Stanza paper](https://aclanthology.org/2020.acl-demos.14/) |

Review dataset and model terms before downloading or redistributing materials. Published datasets provide reference tasks. A frozen sample from permitted source domains is necessary to estimate product performance.

## An experiment that separates sources of error

1. **Before choosing a goal**, measure independent capabilities on their own labeled tasks. Compare structured-field mapping, dates and quantities, and open relation candidates. Use the same input text within each comparison. Retain qualitative error categories and counts so the results help choose a realistic first goal.
2. **After choosing a goal**, write an annotation guide with required roles, optional qualifiers, evidence rules, and examples of ambiguous or missing information. Have two reviewers label a subset and adjudicate disagreements before scaling. Include plausible near misses, such as valid dates tied to a different event.
3. **Freeze the split before tuning.** Keep syndicated or near-duplicate sources together. Hold out publisher domains or a time slice where the intended use calls for it. Keep annotated source snapshots and version the normalizer, rules, and model. Compare alternatives on the same split.
4. **Isolate upstream loss.** Run the same extractor on reference-cleaned text and automatically cleaned text. When using syntax, compare gold or manually corrected linguistic annotations with parser output for a diagnostic subset. This distinguishes missing evidence, parsing errors, and extraction misses.
5. **Score the output at several levels.** Report field precision and recall, strict record matches, and evidence support. Separately report normalized value and role accuracy, false assertions on negative cases, abstention and coverage, and latency. Count a right value attached to the wrong subject or event as a field error. Break down errors by page type and by qualifier, such as negation, attribution, condition, and date scope.

Use strict matching for required roles and normalized values. Use partial-span or paraphrase matching as a diagnostic where multiple textual forms express equivalent content. Score a cited passage's support for the claim through manual checks on a sample. Change one component at a time to see which improvement justifies the added dependencies or complexity.

## Rust implementation options to evaluate

| Need | Candidate |
| --- | --- |
| Pattern baseline | Use the Rust regex project's `regex` for bounded surface patterns and reuse the workspace's `time` and Serde. Keep token rules small until a second extraction goal tests what can be shared. [regex upstream](https://github.com/rust-lang/regex) |
| Linguistic comparator | Use Stanford Stanza or CoreNLP offline as a reference for tokenization, tagging, parsing, or open extraction. Record the treebank and model version. Evaluate whether the extra linguistic layer earns its runtime cost before choosing a production parser. [Stanza upstream](https://github.com/stanfordnlp/stanza) · [CoreNLP upstream](https://github.com/stanfordnlp/CoreNLP) |
| Later local model inference | Hugging Face Tokenizers and Candle are upstream Rust projects to assess for tokenization and model execution. An ONNX model can be benchmarked with the community Rust wrapper `ort`. Confirm model support, release status, resource use, licenses, and workspace compatibility before adoption. A runtime choice still requires a separately selected and evaluated extraction model. [Tokenizers upstream](https://github.com/huggingface/tokenizers) · [Candle upstream](https://github.com/huggingface/candle) · [ort upstream](https://github.com/pykeio/ort) |

Start the research comparisons with structured fields, surface patterns, and a published Open IE reference. Add dependency patterns when the error analysis points to argument attachment. Choose a single downstream question and annotation contract before comparing typed rules with a trained extractor. These are candidate experiments. No local extraction performance has been measured.
